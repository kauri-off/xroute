# XRoute

Android-компаньон и модуль Vector для воспроизведения пешеходного маршрута в выбранном приложении. Идентификатор APK — `io.github.kauri_off.xroute`. Требуется Android 10 или новее, а для передачи координат трекеру — Vector с libxposed API 102 и поддержкой Remote Preferences. Редактор и предпросмотр работают самостоятельно.

## Запуск

1. Установите APK и включите XRoute в менеджере Vector.
2. В области действия XRoute в Vector выберите трекер. Если он один, редактор выберет его автоматически. Если их несколько, выберите нужный из списка в редакторе. После первого добавления перезапустите трекер, чтобы Vector загрузил модуль в его процесс.
3. Касаниями карты расставьте точки в порядке прохождения. Точку можно выбрать по номеру, перетащить, перенести следующим касанием или удалить. «По дорожкам» отправляет от 2 до 50 точек в публичный сервис Valhalla и заменяет ломаную пешеходным путём. Кнопка «Вернуть исходные точки» восстанавливает контрольные точки.
4. Задайте среднюю скорость в км/ч, профиль и скругление поворотов. «Предпросмотр» показывает движение на карте. Длинные маршруты в предпросмотре ускоряются до 24 секунд. У опубликованного маршрута сохраняется заданная скорость.
5. Нажмите «Старт» и включите запись в трекере. «Заново» публикует текущий черновик с новым временем старта. «Стоп» снимает активную сессию. Правки на карте сохраняются отдельно от публикации.
6. «Сохранить…» записывает именованную копию маршрута на устройстве. «Открыть…» восстанавливает точки, исходные точки до построения по дорожкам и настройки движения в редакторе.

## Доставка координат

| Клиент трекера | Поддерживаемые вызовы |
| --- | --- |
| Android LocationManager | Последняя известная GPS-позиция, текущая позиция на Android 11+, обновления для LocationListener через Looper или Executor. Обрабатываются системные батчи, отмена подписки и flush на поддерживаемых версиях Android. |
| Google Play Services | Успешные результаты Task с Location для getLastLocation/getCurrentLocation, потоковые LocationCallback и LocationListener через публичный клиент Fused Location Provider. Адаптер определяет методы в загрузчике классов трекера. |

Модуль обрабатывает обновления, которые провайдер доставляет подписчику с доступом к точному местоположению. Для записи нужны включённое местоположение, действующая подписка и поступающие фиксы. Система или Google Play Services определяет частоту, а также результат отменённых и неуспешных запросов. Подписки через PendingIntent, прямое чтение GNSS/NMEA и клиенты с переименованным публичным API Google Play Services вне охвата этих адаптеров.

Для подходящих длительных подписок порог минимального перемещения проверяется в процессе трекера. Так при неподвижном телефоне новые системные фиксы позволяют пройти требуемое расстояние по маршруту. Пока модуль загружен, такие подписки могут получать больше системных вызовов, в том числе до старта и после остановки. При выключенном воспроизведении отсчёт расстояния ведётся по физическим координатам.

## Контракты

- `Route` принимает 2–2000 точек WGS84, среднюю скорость в м/с, профиль и признак скругления. Прямые участки следуют кратчайшим дугам сферы. Скругление срезает до пяти метров с каждой стороны угла, сохраняя начало и конец маршрута.
- `Route.sample(seconds)` возвращает положение, скорость в м/с и курс в градусах от севера. Продолжительность равна длине фактической геометрии, делённой на среднюю скорость. LINEAR задаёт постоянный темп, SMOOTH — разгон и торможение, WAVE — два цикла изменения темпа. На финише скорость равна нулю.
- Компаньон атомарно записывает строку JSON в группу Remote Preferences `playback` под ключом `session`. Версия 2 содержит `v`, `target`, `startMs` (Unix-время в мс), `meanMps`, `profile`, `roundTurns` и `points` в формате `[[широта,долгота],…]`. Снимки версии 1 читаются с выключенным скруглением. Удаление ключа останавливает воспроизведение.
- `SessionPlayback` проверяет пакет и строит позицию для заданного времени. Один снимок сессии применяется ко всему батчу. Скорость движения привязана к общей отметке старта, поэтому изменение системных часов влияет на прогресс.

## Сборка и проверки

Для сборки нужны JDK 17 и Android SDK Platform 37.2.

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleIntegration :app:assembleIntegrationAndroidTest
```

Устанавливаемая отладочная сборка — `app/build/outputs/apk/debug/app-debug.apk`. Для проверки на эмуляторе используется отдельная сборка с суффиксом .integration. Только в этой сборке тестовый трекер запрашивает точное местоположение. Выберите serial эмулятора явно.

```sh
adb -s emulator-5554 install -r app/build/outputs/apk/integration/app-integration.apk
adb -s emulator-5554 install -r app/build/outputs/apk/androidTest/integration/app-integration-androidTest.apk
adb -s emulator-5554 shell am instrument -w io.github.kauri_off.xroute.integration.test/androidx.test.runner.AndroidJUnitRunner
```

Инструментальные тесты проверяют публикацию через тестовый Binder, чтение активного маршрута только для выбранного пакета, остановку и контракты Google Play Services на классах SDK. Тестовый диспетчер загружает Java entry API 102 и вызывает зарегистрированные перехватчики на сигнатурах Android данного эмулятора. Сквозная проверка записи конкретным трекером требует эмулятора с установленным Vector.

### Подписанный релиз

Gradle читает `keystore/keystore.properties` из корня проекта. Файл содержит `storeFile=xroute-release.p12`, `keyAlias=xroute`, `storePassword` и `keyPassword`. Относительный `storeFile` считается от каталога файла свойств. Тип хранилища по умолчанию — `PKCS12`. Каталог `keystore/` исключён из Git.

```sh
./gradlew :app:assembleRelease
```

Подписанный APK находится в `app/build/outputs/apk/release/app-release.apk`. Если файл свойств или ключ недоступен, сборка релиза завершится ошибкой. Чтобы указать другой файл свойств, добавьте `-PxrouteSigningProperties=/путь/к/keystore.properties`. Относительное значение этого параметра считается от корня проекта.
